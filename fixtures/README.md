# fixtures

Снапшоты РЕАЛЬНЫХ ответов стендов (§9, §10 дизайна). Снимаются вручную:

    HQ_STAND_FORBIDDEN_HOSTS=billing.example.com,panel.example.com \
    HQ_STAND_SHM_URL=http://127.0.0.1:8080/shm/v1 HQ_STAND_SHM_AUTH=<login>:<password> \
    HQ_STAND_REMNA_URL=https://<your-stand> HQ_STAND_REMNA_TOKEN=... \
    pnpm tsx scripts/probe-stands.ts

Каждый файл — `{capturedAt, status, path, params, body}` после редакции.
Кредов в файлах быть не должно: скрипт падает, если после redact в тексте
остались trojanPassword / ssPassword / vlessUuid / privateKey / ssConfLinks.

Тесты читают фикстуры через `fixtureOr(system, endpoint, fallback)`: пока
фикстуры нет, работает рукописный стаб; как только она появилась — тест
сверяется с настоящей формой.

Прод этим скриптом не трогается: он отказывается работать против хостов из
`HQ_STAND_FORBIDDEN_HOSTS` (через запятую; поддомены перечисленных доменов тоже
запрещены). Список задаётся в конфигурации — например в `.env`, который
гитигнорится, а `pnpm probe:stands` его подхватывает, — а не в исходнике:
репозиторий публичный, и захардкоженные там имена были бы адресами чужого прода
в чужом git. **Не задан — скрипт не стартует вовсе**: гейт, который при пустом
списке пропускает всё, хуже отсутствующего, потому что оператор продолжает
считать, что предохранитель на месте.
